# WhereQ App Hub v1.9.5 — shape-geojson

> The map can now hand its drawn polygons and polylines to a JSON file, and draw them again from one.

## What's in this release

- **Export the drawn shapes to a JSON file.** Two new buttons on the map
  tool bar (the file-out and file-in icons) sit next to the capture button.
  The export button writes every polygon and polyline on the map to a
  dated file, `whereq-shapes-YYYY-MM-DD.json`, and says how many shapes
  went into it.

- **Import shapes from a JSON file.** The import button opens a file
  picker and draws the polygons and polylines it holds on the map, then
  moves the camera to them. The shapes come in with the names and
  descriptions from the file, are editable like any hand-drawn shape, and
  behave identically everywhere else — they can be grouped, saved and
  exported again.

- **The file format is GeoJSON (RFC 7946), not a bespoke one.** The file
  is a standard `FeatureCollection`, so it opens as-is in QGIS, Google
  Earth and ArcGIS. A position is written as `[longitude, latitude]`
  (GeoJSON's order, the opposite of the Maps API's), and a polygon's
  outer ring is closed and wound counter-clockwise, exactly as the
  standard asks. The app's own metadata rides along in a `whereq` member
  beside the features.

- **A file that is not a shape file is refused; one bad shape is not.**
  A file that is not a shape document at all is turned away with a plain
  message. But a single feature that cannot be used — a point, a ring
  with too few vertices, a position out of range — is skipped and
  counted, so one bad shape never costs you the rest of the file. The
  notice says how many were drawn and how many could not be read.

- **The toolbar waits for the map before it claims success.** The tool
  bar lives outside the map component and cannot reach the map itself, so
  the shapes travel over the app's event bus to the component that owns
  the map, which draws them through exactly the same code path a
  hand-drawn shape takes. The "Added N shapes to the map" notice waits
  for that component's answer, so a map that is not ready can no longer
  be mistaken for a successful import.

## Notes

- The release notes live in `docs/releases/v1.9.5-shape-geojson-2026-11-21.md`.
- The git tag for this release is `v1.9.5`.
- Status is `shipped`, set by `--status`.
- Only polygons and polylines are exchanged. Markers, circles and
  rectangles are not paths, and a circle has no GeoJSON equivalent, so
  they stay in the app.
