# WhereQ App Hub v1.8.3 — note-correction

> The v1.7.0 notes said something that turned out not to be true. This
> is the correction.

## What's in this release

- **The v1.7.0 release note no longer says the address search needs an
  IP-restricted key.** It did, and it was wrong: the map's address search
  geocodes free text with the browser's own Google Maps geocoder, which
  accepts a key restricted to web addresses — the search box keeps
  working with your ordinary key. What Google refuses is the *Geocoding
  web service*, the server-side one the lab does not use, because that
  one only takes keys restricted to IP addresses. The corrected line is
  marked as such in the note.
- **The architecture notes carried the same wrong claim**, in the
  list of known issues. That entry now states what was actually measured
  against the live API: a free-text search returns a result and places a
  marker with a referrer-restricted key.

## Notes

- **Nothing in the app changed.** This release only corrects two
  sentences of documentation; the code is identical to v1.8.2.
- **How the claim was settled:** against the live API with the real key,
  the free-text search answered `200` with a geocoding result and the
  map placed a marker at it.
- **The release notes live in
  `docs/releases/v1.8.3-note-correction-2026-11-20.md`.**
- **The git tag for this release is `v1.8.3`.**
