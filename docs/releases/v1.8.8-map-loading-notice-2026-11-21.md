# WhereQ App Hub v1.8.8 — map-loading-notice

> When the map cannot start, the app now says so instead of showing an empty
> grey box.

## What's in this release

- **The map no longer fails silently.** Occasionally the map area stayed an
  empty grey box — no tiles, no error message, nothing to click. The page now
  reports what it is doing: after 8 seconds without a single tile it shows
  *"Loading the map…"*, and if nothing has drawn by 20 seconds it shows
  *"The map didn't load."* together with a **Try again** button that reloads
  the page. A healthy map shows neither message.
- **The map now uses the dedicated WhereQ.ca Google Cloud project.** The site
  runs on its own API key and map ID (`whereq-ca`) instead of the shared key
  used by the other WhereQ apps, so WhereQ.ca's map usage is tracked and
  billed separately. Visitors who have saved their own key in the settings
  panel still take precedence — nothing about the BYOK model changed.

## Notes

- **Why the map could come up blank.** A vector map is a pipeline of requests:
  the loader script, then the map configuration, then the vector renderer,
  then the map style, and only then the tiles. If the browser drops one of
  them, the page shows an empty grey box that is indistinguishable from a
  broken app — Google logs no error and the map DOM is only half-built.
- **How it was diagnosed.** Measured in a real browser against the live site:
  the failure is independent of the API key and the map ID (the previous,
  known-good credentials fail the same way), and the map-configuration
  response is byte-for-byte identical between a working run and a blank one.
  The difference is downstream of it — in a blank run the renderer and style
  requests are never made, so no map canvas is created at all. Chrome also
  throttles animation frames hard in a backgrounded page, and the vector
  renderer drives itself from them.
- **Why "Try again" reloads the page.** A fresh page load is the only thing
  that re-issues the dropped request; nothing else in the page can.
- **How this was checked:** in real Chrome on the live site, the map paints,
  the camera still moves on both the suggestion-pick and the free-text search
  paths, the settings panel still covers the map area without overlapping the
  header, the left bar or the footer, and the console is clean. The two
  notices were verified by deliberately blocking the renderer request: the
  loading notice appears at 8 seconds, the "didn't load" message with its
  button at 20 seconds, and neither appears on a healthy map.
