# WhereQ App Hub v1.8.2 — marker-events

> The map's markers now use Google's current element API, so the console
> stops warning about them.

## What's in this release

- **Markers are clicked the way Google wants them clicked.** A marker now
  listens for Google's `gmp-click` event on the marker itself, instead of
  the old `click` event on the marker's DOM element. The old form is
  deprecated by Google and prints a warning in the browser console on a
  vector map.
- **Markers are now keyboard reachable.** A marker is created as clickable,
  which is what makes it respond to the keyboard and be announced by a
  screen reader, not just to the mouse.
- **The pin is passed over as itself.** The marker used to be handed the
  inner DOM element of its pin, which Google also deprecated — the pin
  object is now passed directly, which is the supported form.
- **A repeated click no longer stacks up handlers.** Picking a second
  place used to leave the first place's click handler attached, so one
  click could open the marker dialog twice. Each handler is now removed
  when the place changes.
- **The documentation records the rules**, so the next person does not have
  to rediscover them from a console warning.

## Notes

- **Nothing visible changes.** Clicking a marker still opens the marker
  dialog, and clicking a drawn marker still highlights it and highlights it
  again on the next click. All of it was verified on a real browser against
  a live vector map.

  `docs/releases/v1.8.2-marker-events-2026-11-19.md`.**
