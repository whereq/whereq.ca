# WhereQ App Hub v1.9.0 — map-search-redesign

> The `/map` search bar now looks like the one on whereq.com — one clean field
> with a magnifier, a clear button and a proper dropdown.

## What's in this release

- **The map search bar was rebuilt on whereq.com's pattern.** It used to be a
  bare grey rectangle with a bright orange monospace placeholder and a separate
  grey **Search** button sitting next to it. It is now a single bordered field:
  a magnifier on the left, the input in the middle and a clear (**×**) button
  on the right, with the suggestions dropping out of the field as one panel —
  the same shape as the sidebar search on whereq.com.
- **The magnifier is the Search button.** Clicking it (or pressing Enter)
  submits the query: a query with suggestions picks the highlighted one, a
  query without one is geocoded. The old separate Search button is gone, so
  the field is no longer crowded by two controls.
- **The orange is out of the text.** The placeholder is a muted grey and the
  text you type is the app's cream colour; the accent orange is kept for the
  highlighted suggestion, so the box stops shouting and the selection stands
  out.
- **The suggestion list was restyled to match.** It is the width of the field,
  with a muted border and a soft shadow, cream place names and grey context
  lines, and the first suggestion highlighted in the accent colour.

## Notes

- **Why the input sets `text-left` explicitly.** The app shell centres
  everything (`ShellLayout` puts `text-align: center` on the page container),
  and an input inherits it — the text would have sat in the middle of the
  field. The same trap is documented in `docs/ARCHITECTURE.md` §13.
- **The search behaviour itself is unchanged.** The 250 ms debounce, the one
  autocomplete session per search (which is what keeps the search billed as a
  single request), the request-id guard against a slow answer overwriting a
  newer one, and the `toPlace()` → `fetchFields()` resolve all stay as they
  were. Only the chrome changed.
- **How it was checked:** `tsc` clean, lint unchanged at 0 errors / 29
  warnings, production build green, and the field verified in a real browser
  against the local preview — the magnifier, the clear button, the dropdown and
  its highlight all render, five suggestions come back for a typed address, a
  picked suggestion fills the box with the resolved place, the magnifier fires
  the place-details call when there is a suggestion and the geocoding call
  when there is not, and the console is clean.

  `docs/releases/v1.9.0-map-search-redesign-2026-11-21.md`.**
