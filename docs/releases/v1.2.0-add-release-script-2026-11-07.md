# WhereQ App Hub v1.2.0 — the release pipeline

> **One command from a clean tree to a live deploy — with the gates that keep the video engine alive.**

Until now, releasing this app was a ritual of muscle memory: run the lint,
remember the type-check, watch the header diff, commit, push, and *hope* the
FFmpeg engine still boots in production. This release turns that ritual into
`bin/release.sh` — the same release shape the rest of the whereq universe
uses.

## What's in this release

- **`bin/release.sh`** — the release entry point. It runs the CI gates,
  commits, squashes, pushes `dev`, merges to `main`, tags, and pushes. There
  is no `deploy.sh`: **pushing to `main` is the deploy**, Vercel does the
  rest.
- **Four gates that used to be manual** — COOP/COEP/CORP header parity
  between `vite.config.ts` and `vercel.json`, `yarn lint`, a full type-check,
  and `yarn build`. A failing gate aborts the release before anything is
  committed.
- **A type-check that actually passes** — the eleven TypeScript errors that
  had been hiding behind `vite build` (which never type-checks) are fixed.
  The map hooks now use React 19's nullable ref types, the Pyodide stream
  typing is honest, the Ace editor has real prop types, and the stale
  `@ts-expect-error` directives on `gifuct-js` are gone.
- **`dev` as the working branch** — `main` stays the deploy branch, the way
  the other whereq apps run.
- **Release notes that scaffold themselves** — the script writes
  `docs/releases/v<version>-<codename>-<date>.md` with the right front-matter
  before it tags.

## The COOP/COEP contract, enforced

The single most load-bearing piece of configuration in this app is the trio
of cross-origin headers that let `SharedArrayBuffer` exist. If `vite.config.ts`
and `vercel.json` disagree by one character, FFmpeg.wasm and ONNX Runtime
fail to load — silently, in production, with no console error worth reading.

That failure mode is now a build gate rather than a surprise:

```
━━━ Step 1: Check COOP/COEP/CORP header parity
    ok       Cross-Origin-Opener-Policy: same-origin
    ok       Cross-Origin-Embedder-Policy: require-corp
    ok       Cross-Origin-Resource-Policy: cross-origin
```
