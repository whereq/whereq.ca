# WhereQ App Hub v1.8.5 — settings-layout

> The map's settings table was rendering as one long stack of labels and
> values instead of four columns. Here is why, and what it looks like now.

## What's in this release

- **The map settings table has its columns back.** It was drawn with
  `grid-cols-[5%,20%,35%,40%]`, which compiles to
  `grid-template-columns:5%,20%,35%,40%` — and a grid track list is
  space-separated, not comma-separated. The browser kept the selector and
  dropped the declaration, so the table fell back to a single column and every
  cell stacked underneath the previous one. The correct Tailwind arbitrary
  value uses underscores: `grid-cols-[5%_20%_35%_40%]`.
- **The settings table is a real table now.** The panel renders a `<table>`
  with a sticky header row, so the column headers stay put and the browser
  keeps the columns aligned. The setting name is a row header, which is what
  a screen reader announces when it reads a row.
- **The notice above the table is readable again.** It was a single centred
  block of text stretched across the full width of the screen. It is now
  left-aligned and limited to a comfortable line length, and it carries a
  **Using the shared WhereQ key** badge when the map is running on the shared
  WhereQ key rather than on your own.
- **The checkbox column does something now.** Ticking a row and pressing the
  new trash button empties that field — the quick way to go back from your own
  key to the shared one. The button stays disabled until something is ticked.

## Notes

- **The same bug was in the api-explorer settings panel.** It had the identical
  comma-separated grid value and collapsed the same way. Fixed there too.
- **Why it was so easy to miss:** the failure is invisible in the source, and
  in DevTools the rule still looks like it is there. Reading the CSSOM is
  what shows it: the parsed rule is `.grid-cols-\[5\%\,20\%\,35\%\,40\%\] { }`
  — the selector survived, the declaration is gone.
- **How this was checked:** against a local production build at 1600×900 and
  1280×800 — four columns with the header and the row on one line each, no
  horizontal overflow, the notice left-aligned, the shared-key badge present,
  and the select → clear → save round trip storing an empty string rather than
  a copy of the shared key.
