# WhereQ App Hub v1.9.3 — lab-universe-redesign

> The Lab hub now speaks the WhereQ universe's visual language — a composed masthead instead of a paragraph — and a new demo page puts the open-source @whereq/react library on show.

## What's in this release

- **A masthead, not a paragraph.** The Lab header used to be a kicker, a heading and one long line of text. It is now a composed editorial block: a mono kicker over a hairline rule, a tight display title, a lede constrained to a readable measure, a "Back to the Universe" call to action, and a **fact rail** on the right (13 experiments · 6 UI primitives · runs in your browser · keys stay on this device). Everything is explicitly left-aligned, because the app shell centres whatever it renders.
- **A grid you can search and filter.** The Lab now has a toolbar with the shared `@whereq/react` `SearchBox` — type "map" and the grid narrows to the matching experiments, pick a suggestion and it opens — plus a row of category chips (Developer, Media, Geo, Productivity, Science, Learning, Fun, Design System) that filter the grid further.
- **A new experiment tile.** Each card is now a framed icon tile with a name, a one-line description and a category tag, instead of a big centred glyph with the description hidden. The tiles are the Universe's origin cells, drawn in the app's own tokens.
- **A new card: WhereQ React.** The Lab's grid carries a thirteenth experiment, `@whereq/react` — the open-source component library every WhereQ app is built from. Its page at `/react` is a **live demo**: the rail on the left holds one button per primitive, the workspace shows the real component from the published package with its code snippet, and the panel on the right documents the library. The child pages are `SearchBox`, `Tag`, `Toast`, `Avatar`, `Scrollbar` and `CountryFlag`.
- **Two library bugs fixed on the way.** Building the demo surfaced two real defects in `@whereq/react`, both now fixed and published: the toast's tinted background and border were built as `var(--up)/10`, which is not valid CSS, so a success/warning/error toast rendered with **no background and no border**; and the `solid` variant of `Tag` built its colour classes at runtime, which a consumer's Tailwind can never compile, so the pill rendered unpainted. The app now uses `@whereq/react` 0.9.4.

## Notes

- The Lab hub and the demo share a new set of `--uq-*` tokens on `:root` (`src/index.css`) — the Universe's deep-space palette, the same one the landing page at `/` uses. The MetroUI orange palette is still what the older feature pages use; the two are not mixed on one surface.
- The app shell centres everything it renders, and that alignment is inherited. Both new surfaces set `text-align: left` on their root for exactly this reason.
- `@whereq/react` ships a few components whose markup is written with Tailwind utility classes. Those class names live in the published bundle, which Tailwind never scans on its own, so `src/index.css` now points `@source` at `node_modules/@whereq/react/dist/**` — without that line the library renders unstyled.
- Verified in a real browser against the production build: the masthead and the fact rail render, the search box narrows the grid and the chips filter it, the demo opens with the workspace on the SearchBox child page, the toast paints with its tint and the solid tag paints its pill. No console errors.
