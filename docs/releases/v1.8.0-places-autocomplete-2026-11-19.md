# WhereQ App Hub v1.8.0 — places-autocomplete

> The map search now shows its suggestions again — the list Google used
> to draw for us stopped being drawn, so we draw it ourselves.

## What's in this release

- **The search box suggests places again.** Google's address-suggestion
  widget was closed to new customers in March 2025. It still loaded and
  still asked Google for suggestions, but it no longer showed them: the
  list stayed empty, so the search box looked broken — you typed, nothing
  appeared, and the only way to search was to press Enter and hope. The
  map now uses Google's current suggestion API and draws the list
  itself, in the same dark style as the rest of the lab.
- **Suggestions you can pick from with the keyboard.** Arrow keys move
  through the list, Enter picks the highlighted entry, Escape closes it,
  and a click works too. The first suggestion is highlighted as soon as
  the list appears.
- **Free-text search still works.** Text that matches no suggestion is
  still looked up by address, and when nothing matches at all the map
  says so plainly ("No match found for that search.") instead of
  failing quietly.
- **A cleaner search internals.** The whole session of one search is now
  billed as a single request instead of one request per keystroke, a
  slow answer can no longer overwrite a newer one, and clearing the box
  cancels the lookup that was still running.
- **The old widget is gone from the app.** The deprecated suggestion
  class was removed from the live map feature and from the older,
  unwired map copy as well.

## Notes

- **Bring your own key.** The map feature is BYOK: the key lives in your
  browser's local storage and is never sent to WhereQ.
- **Give the key the whole site, not just the home page.** Google compares
  the path of the page that was loaded, so a key restricted to
  `https://www.whereq.ca` alone is refused on `/map`, `/lab` and every
  other route with "This IP, site or mobile application is not
  authorized to use this API key". To allow the whole site, list
  `https://*.whereq.ca/*` and `https://www.whereq.ca/*` (plus
  `https://whereq.ca/*`, and `http://localhost:4173/*` if you work on it
  locally). A path wildcard that follows a literal segment — for example
  `https://*.whereq.ca/map/*` — does **not** cover `/map` itself: it
  needs at least one more segment after the slash.
- The map drawing tools, the marker placement and the advanced markers
  were re-tested against the live API after the change: drawing a
  rectangle, a circle, a polygon, a line and a marker all still work.
