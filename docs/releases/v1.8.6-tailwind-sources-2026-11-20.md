# WhereQ App Hub v1.8.6 — tailwind-sources

> Following v1.8.5: the fix for the settings table was partly undone by this
> project's own documentation. Now it cannot happen again.

## What's in this release

- **Only the app's own files can contribute CSS now.** Tailwind v4 scans the
  whole project for class names by default, and that includes Markdown. A
  class name written in a doc, a release note or a code comment was compiled
  into the stylesheet. The build now registers its sources explicitly —
  `src/**/*.{ts,tsx,js,jsx}` and `index.html` — and excludes Markdown.
- **The invalid rule is gone for good.** Writing down the broken class name
  while documenting the v1.8.5 fix re-created the exact rule that fix was
  about: `.grid-cols-\[5\%\,20\%\,35\%\,40\%\] { grid-template-columns: 5%,20%,35%,40% }`
  — a declaration the browser rejects. The class was unused by the app, so
  nothing broke, but the stylesheet carried dead, invalid CSS that only
  existed because a document mentioned it.
- **A second piece of accidental CSS went with it.** The word "collapse" in a
  Markdown sentence was enough for Tailwind to emit a `visibility: collapse`
  utility that the app never uses.

## Notes

- **This was not visible in the source or in DevTools.** The rules look
  correct in the built file and the elements match them; the browser simply
  discards the invalid declaration. Reading the CSSOM is what shows the
  truth: the parsed rule has a selector and an empty body.
- **How this was checked:** the scoped and unscoped stylesheets were built and
  their selector sets diffed. The scoping removed exactly two selectors — the
  invalid comma-separated grid and the accidental `collapse` — and added none.
  Every other utility the app uses is untouched. All routes still return 200
  and render.
